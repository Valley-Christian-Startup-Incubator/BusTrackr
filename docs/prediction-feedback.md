# Prediction feedback

Riders report from either web view. Simple shows "Actually, the bus is here now" under the last detection time. The map view's camera panel shows "The bus is here" while the feed is current, and "Looks wrong" while an estimate is shown. The point is ground truth: each report says what a person saw next to what the system predicted at that moment.

## Record

The worker appends one JSON object per line to `FEEDBACK_FILE` (default `<ALERT_STATE_FILE>.feedback.jsonl`). It never rewrites the file.

```json
{"id":"…uuid…","receivedAt":"2026-11-09T15:08:00.000Z","verdict":"arrived","view":"simple",
 "collector":{"commit":"f15017a","release":"f15017a8c2d1…"},
 "prediction":{"model":"learned-runs-v1","status":"scheduled","runId":"run-1512","nextCrossingAt":"…","quality":{…},…}}
```

- `verdict` is `arrived` (the rider saw the bus at that time) or `wrong` (the shown estimate looked wrong).
- `view` is `simple` or `map`. Simple riders saw only the time since the last detection, not an estimate.
- `prediction` is the server's own `/api/shuttle` prediction when the report arrived, not a copy sent by the client. `model` names the estimator and `quality` is its backtest score at that moment.
- `collector.commit` is the worker's `BUSTRACKR_COMMIT`. It stays `null` until the worker is deployed from git (issue #24). `collector.release` is the web app's `bustrackr-release` meta tag, written by the deploy controller.
- `id` is generated by the browser, once per verdict. A retried request with the same id is stored once, across restarts too.

`POST /api/feedback` takes `{"id","verdict","view","release"}` as JSON. It is rate limited to 10 requests per minute per client IP and accepts the same browser origins as the rest of the API.

## Reading it

`arrived` reports against `estimatedArrivalAt` or `nextCrossingAt` give a direct error per model. `arrived` reports while `status` is `unknown` or `unconfigured` point to buses the camera or the learned runs missed. Reports are not training input: a rider can be wrong, and the camera is the only ground truth the model learns from.

```sh
jq -c 'select(.verdict=="arrived" and .prediction.status=="estimated")
  | {model:.prediction.model, errorSeconds:((.receivedAt|sub("\\.\\d+Z$";"Z")|fromdate)-(.prediction.estimatedArrivalAt|sub("\\.\\d+Z$";"Z")|fromdate))}' .data/feedback.jsonl
```
