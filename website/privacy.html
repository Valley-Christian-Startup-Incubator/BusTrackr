Privacy

BusTrackr has no accounts or ads. The website and web app use self-hosted analytics to measure visits and campaign links. The native apps contain no analytics SDK.

Last updated November 2, 2026. This page describes the current app source. Push notifications require a configured deployment.

The iOS and Android apps

  • The app saves your status URL or sample scenario, your Simple or Map display preference, and your notification opt-in and subscription management credentials on your device.
  • It doesn't request location permission and doesn't use GPS.
  • It doesn't save camera observations between launches.
  • It contains no analytics or advertising SDK.

While the app is open, it requests the status URL every ten seconds. The server that answers can see ordinary request details such as your IP address. The bundled 3D scene makes no network requests.

On iOS, the app may ask for local network access if you connect it to a status server on your own network.

This website

This site sets no analytics cookies. It loads Umami from our self-hosted server at analytics.bryanhu.com to count page views and measure campaign links, including Instagram story links. Analytics includes the page URL and its campaign parameters, referring page, browser, device and approximate location derived from the request. Do not put personal information in link parameters. We do not enable session recording. The home page also requests /api/shuttle from this same server while the page is visible to show feed status and retry temporary connection failures.

The 3D web app

The web app is hosted with this website on our server. Requests pass through Cloudflare under the privacy policy linked below. It also loads fonts from Google Fonts, so Google can see your IP address under the Google privacy policy. The web app uses the same self-hosted Umami analytics described above, without analytics cookies or session recording.

The status server

Requests to this site and to /api/shuttle reach the server through Cloudflare, which handles them under the Cloudflare privacy policy. The status server does not log individual requests or store visitor analytics. The separate Umami server stores the visit analytics described above.

Camera alerts

A camera at the checkpoint emails an alert when a bus enters its zone. Resend receives those emails and notifies the server, which reads each message and keeps only:

  • the camera's event time, the email's date, the time the email arrived, and the checkpoint name
  • a hash of the email's message ID, plus receipt and delivery IDs, used to skip duplicates and retries

The server doesn't store email bodies or attachments in its history. When it must check the signature on a forwarded email, it reads the raw message, up to 2 MB, and doesn't keep it.

The public feed exposes the latest observation, the number of saved alerts and the current prediction. There is no public history endpoint. History stays on the server, with no automatic deletion schedule.

Optional bus notifications

Notifications are off until you choose to enable them. The app requests notification permission and sends its push token or browser push subscription to the status server. The server stores that subscription, a hash of its management secret, its creation time, and delivery records. It does not associate the subscription with an account, name, email address or location.

New camera detections can trigger a message through your browser's push provider or the Expo Push Service and Apple or Google notification services. Those services process the push token and notification content. BusTrackr does not send you old camera history when you subscribe.

Turning notifications off removes the server subscription when the request succeeds. The app displays a failure if it cannot complete that request. Delivery records are pruned after 24 hours while notification processing runs. Subscriptions stay until you turn alerts off or the push provider reports that the device is no longer registered.
